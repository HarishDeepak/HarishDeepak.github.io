Six cubes, one tower, a real Panda

A Franka Panda finds wooden cubes on a table, picks them one by one and stacks them into a tower. It was built in Gazebo first, then run on the physical robot. Afterwards the whole stack moved from ROS Noetic to ROS 2 Humble.

Robot
Franka Panda, ZED2i
Stack
ROS Noetic, MoveIt, TRAC-IK
Perception
GroundingDINO + SAM, Open3D
Code
irobman_project

Perception: from a word to a pose

The default pipeline prompts GroundingDINO with the word "cube", segments with SAM, back-projects the masks into the ZED point cloud and fits a cube to each cluster with ICP, using the table plane as a constraint. A classic mode (filtering, DBSCAN, ICP) stays as a fallback. Fusing a few frames before fitting made the poses steadier, and anything outside a safe area on the table is ignored.

Motion: one snapshot, then commit

The stacker takes a single snapshot of cube poses, picks a tower spot near the base, and always takes the cube furthest from the base next. Each pick goes approach-from-above, align, grasp, attach to the MoveIt scene, carry, release. The placed cube is then added back to the scene as an obstacle, so later moves plan around the tower.

The ROS 2 port

Moving to ROS 2 Humble meant a new control layer: the Panda URDF got a ros2_control block and the gazebo_ros2_control plugin, a joint trajectory controller replaced the old one, and MoveIt 2 took over planning, all in Docker on Ubuntu 22.04. Seven problems along the way (URDF constraints, controller-manager timing, plugin load order) are written up in the repo with their fixes.

Where the port stands

Simulation, control and MoveIt 2 planning run in ROS 2. The perception and stacking nodes are ported but not yet wired together, so the ROS 2 version does not stack cubes end to end yet.
